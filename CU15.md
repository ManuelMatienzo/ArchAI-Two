# CU-15: sugerencias compartidas

En el estudio, abrir **@ArchAI** para solicitar sugerencias sin cambiar el diagrama oficial. El panel usa los estilos del estudio. Los avisos flotantes abren la conversación. La vista previa y aprobación pertenecen a próximas entregas.

Solo el anfitrión controla las sugerencias automáticas y el permiso de observación en nube. Las revisiones automáticas priorizan Ollama y permiten respaldo en nube con ese permiso. Las consultas manuales respetan el selector Local/Nube. El estado se mantiene en memoria y se pierde al reiniciar. No hay migraciones ni cambios de esquema.

En **Preferencias del asistente → Modelo local** se consultan los modelos instalados y se elige el usado por este navegador. **Conectar** comprueba disponibilidad en Ollama; no ejecuta inferencia ni prueba la calidad del modelo. La selección se conserva localmente, sin migraciones. Por defecto se elige `qwen3.5:4b`, con `think: false`, y cada propuesta identifica proveedor y modelo real utilizado. Si el modelo elegido ya no existe, se informa el error y no se sustituye por otro local arbitrario; el respaldo en nube conserva las reglas anteriores.

## Entorno local aislado

Vite carga `VITE_GEMINI_API_KEY` y `VITE_GEMINI_MODEL` del `.env` en la raíz del repositorio. Si están definidas también en `frontend/.env`, se prioriza la configuración del frontend. Las variables del proceso mantienen la prioridad de Vite. Solo esas dos variables se incorporan desde la raíz al cliente; las variables de base de datos y `GEMINI_API_KEY` del servidor no se exponen con esta carga. Reiniciar Vite después de cambiar valores del `.env`. Las claves con prefijo `VITE_` son públicas para el navegador, como en la integración existente.

Backend: `mvn spring-boot:run '-Dspring-boot.run.profiles=local-test'`. Este perfil fija H2 en memoria para que Spring no use PostgreSQL. Frontend: `npm ci` y `npm run dev`. Ollama: iniciar el servicio y descargar el modelo predeterminado con `ollama pull qwen3.5:4b`, o elegir otro instalado desde las preferencias. Las llamadas locales usan el proxy Vite existente. Para probar nube, configurar las variables VITE_GEMINI_API_KEY/VITE_GEMINI_MODEL en el entorno de Vite; no subir claves. Las credenciales del cliente son visibles para el navegador, como en la integración previa.

## Verificación

El selector **Motor para tus consultas: Local / Nube** controla los envíos manuales. Local solo usa Ollama y nunca pasa a nube; Nube usa directamente Gemini. Al recargar vuelve a Local. No cambia los controles compartidos de revisiones automáticas: estas priorizan Ollama y solo permiten respaldo cloud cuando el anfitrión activa Observación en la nube. El cambio de motor se aplica a nuevas consultas y está deshabilitado mientras existe una propuesta pendiente.

Abrir dos usuarios en la misma sala y un tercero en otra. Solicitar una sugerencia y comprobar recepción, ausencia de duplicados, aislamiento de salas y que el diagrama no cambie. Cambiar atributos y esperar cinco segundos; mover nodos no debe generar consultas. Desactivar observación en nube antes de probar indisponibilidad de Ollama. No hay garantía de latencia: depende del modelo y hardware.

Pruebas de coordinación: `mvn test`. Las pruebas de Spring usan su configuración H2 de test. La revisión automática se limita a una cada 30 segundos por sala y requiere al anfitrión conectado.
